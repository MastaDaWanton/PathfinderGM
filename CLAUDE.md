# Pathfinder GM

An application that lets one person play a Pathfinder campaign inside a world generated by
**World Bible** (`H:\coding\WorldBible0.0`, published at
https://github.com/MastaDaWanton/World-Bible).

World Bible writes the world. This app runs the game in it. The boundary between them is a
file, not a shared codebase: see `docs/from-world-bible.md` for the handoff and
`docs/campaign-format.md` for the contract. A real exported world sits in `fixtures/` so
there is no need to run World Bible to develop against real data.

---

## Standing constraints

These carry over from World Bible and are not up for renegotiation without asking:

- **Ships as a standalone `.exe`.** The user installs one file. No terminal, no
  `pip install`, no Python knowledge required to run it.
- **Quality of output beats build speed.** Local test runs cost nothing but time; a slower
  pipeline that produces better play material is the right trade every time.
- **Local models by choice.** Ollama on the user's own machine (`llama3.1:8b` generator,
  `deepseek-r1:8b` proofreader in World Bible). Slowness is the price of privacy and zero
  cost, and the manual should say so. Hosted providers must remain possible, never required.
- **Anything available in a browser must also work in the packaged desktop app.** A feature
  that only works under `runserver` is not finished.

## The rules that were learned the hard way

Every one of these cost real debugging time in World Bible. They are not style preferences.

### Working with models

- **Detect mechanically, repair with a targeted call.** Every quality fix that held used
  this shape: find the defect in code (a regex, a set comparison, a count), then ask the
  model to fix only what was found. Every fix that relied on instructing the model to
  behave differently failed and kept failing.
- **The shape of a prompt becomes the shape of the output.** An instruction reading "say
  what it COSTS" produced ten consecutive paragraphs ending "However, it costs the
  clans...". If output is formulaic, suspect the instruction before the model.
- **A model asked for N things answers in parallel.** Five factions in one call came back
  with five identical sentence skeletons; writing them one at a time, each shown what the
  earlier ones already did, removed it at the source.
- **Ground every name.** Given freedom, a model invents places and people that do not
  exist, then treats them as settled fact. Pass the world's real names and check the output
  against them.
- **Instruction volume loses to demonstration volume.** 368 characters of "write about
  anatomy" against 6,469 characters of social prose produced more social prose. Fix the
  ratio, not the wording.
- **Verify end to end, on real regenerated content.** Synthetic fixtures and regex metrics
  have repeatedly given confident, wrong answers about quality.

### Packaging and the frozen app

- **Never anchor a path on `__file__` in code that will be frozen.** It points inside the
  PyInstaller bundle and says nothing about where the app was installed. Use the
  executable's own location.
- **Derived caches in the user's data directory outlive every reinstall.** World Bible
  served a five-day-old stylesheet across four versions because a staleness check silently
  answered "fresh". Version-stamp anything cached outside the install directory, and
  compare content, not just timestamps.
- **Prove packaging fixes against the packaged build.** Run the built executable against a
  throwaway data directory seeded to reproduce the bad state. Twice, this turned a
  plausible theory into a fact — and once it disproved the first fix, which had already
  looked correct.

### Everyday traps

- **Bash heredocs mangle backslashes.** `\b` has been written into source as a literal
  backspace byte more than once, silently breaking a regex while tests still passed. Use
  the Write/Edit tools for anything containing escapes, or build them with `chr(92)`.
- **When you fix a rule, grep for every copy of it.** A consequence rule was corrected in
  the main prompt and left stale in the rewrite prompt; the bug carried on shipping from
  the copy nobody looked at.
- **Empty is not the same as absent.** A partial save that ignores unsent fields will
  silently refuse to clear a list — the form has to declare that the editor was on screen.
- **A hidden required field kills a submit with no error at all.** The browser blocks it
  and cannot show a validation bubble on a `display:none` element. Nothing happens, and
  nothing says why.
- **`new FormData(form)` omits the submitter.** A form with two buttons cannot tell the
  server which was pressed unless the submitter is passed in.

## How work is expected to be done

- **Tests document the defect they prevent.** Name the measurement in the docstring — "ten
  of ten paragraphs ended the same way", "674px of content in a 617px box". A test that
  only asserts behaviour gets deleted by the next person; one that records what went wrong
  survives.
- **Run the whole suite, not the file you touched.** World Bible ended at 462 tests and the
  full run takes seconds.
- **Comments explain why, including what was tried and rejected.** Match the density of the
  surrounding code.
- **Verify in the running app**, not only in tests — drive the real UI and read the real
  output before calling something done.
- **Report honestly.** If something is half-done, blocked, or was measured and still fails,
  say so plainly with the numbers.
