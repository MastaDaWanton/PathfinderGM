# Lane B research, 2026-11-22: reading the regex spell layer

## The question
354 spells carried mechanics only from `content/spells/spells-mechanics.json`, a regex over
the prose (`rules/spells.py:read_scaling`). The audit measured them as "FULL" because the
engine ran them, not because anybody had checked them.

## Prior art consulted
- **PF1e primary text.** Every reading was taken from the corpus's own printed lines and
  description (`content/spells/spells.json`, the Codex import of the PRD text), by eight
  reader passes, each validated by `effectspec.validate` and a casting-plan dump at caster
  levels 1/5/10/15 (`impl-b-scratch/check_reading.py`), then a review pass of the plans
  that rolled dice. The web escape rule and resist energy's steps are the CRB's text as
  the corpus prints it (aonprd.com SpellDisplay pages for Web and Resist Energy carry the
  same words); they were not re-fetched this session.
- **Foundry PF1 / PCGen / Roll20.** I searched for how they turn spell text into rolls and
  could not confirm the PF1 Foundry system's data model from a primary source (the search
  surfaced PF2e's formula engine and an alpha PF1 damage module, not the system's docs).
  Roll20's Pathfinder sheet parses dice expressions out of a spell's damage and description
  fields into inline rolls (https://wiki.roll20.net/Pathfinder_Official), which is the
  shape this lane removes: a displayed roll is fine, an executed one needs a person's
  reading. Not sourced further.
- **Fate / the audit's §4 rule 4**, "no scripts in data: a closed set of executors with
  validators that name the fix", is what `effectspec.validate` already is; every reading
  passed it.

## What reading found (counts from verdicts-all.json)
- 354 read; **231 wrong**, 75 incomplete, 48 right.
- The commonest wrong shapes, by hand count of the verdicts:
  - damage the target never takes on casting (a mishap, a trap, a later attack, a
    retribution, a per-round hazard, the caster's own cost) rolled at the target;
  - damage put behind a save that only stops a rider (chill touch, sound burst);
  - a "half" save read as "negates" or "partial" and dealing 0 (thundering drums, shout);
  - inflict spells typed untyped instead of negative;
  - a missing cap (blight to 15d6, force anchor 5d4).

## Engine gaps the reading exposed, and what was done
1. `casting_plan.take()` dropped a gate's other branches: fixed, they stay a rider under
   the same (cached) save.
2. A printed "partial"/"negates" line overruled a reading that halves: for a read spell
   the branches decide now.
3. Type-limited damage (disrupt undead, destroy robot) hit anybody: the core's `when` is
   asked per target.
4. A holder-less grapple (web) could never be escaped: `ends_when.escape` and the
   `escape` op.
5. A regex `scaling` outlived the reading that replaced it: dropped on load.

6. Ability damage in a gate's branch was told, never dealt: `_magic_gate` deals it.
7. A choice whose option is a gate (blindness/deafness, command) rolled no save: the
   chosen option's save is rolled with the cast's other rider saves.

## Owner calls (RAW taken, not ruled)
- A spell with any told part is not bottled (`formulae._executable_all`). Read honestly,
  280 regex-layer spells now carry a told part, so they no longer derive a potion or
  flask (145 derived rows remain); the regex had hidden their other halves. Burning hands'
  flask is gone because its flames setting things alight is told.
- Type-limited damage with no type to ask (shatter's "crystalline creature") fails closed:
  nothing in the bestiary carries the subtype, so shatter harms no creature.
- Alignment-limited damage (holy smite, chaos hammer, burst of radiance) hits any target,
  per the 2026-10-05 ruling that alignment clauses hold against any foe until alignment
  is tracked.

## Not sourced / not done
- A partial save whose success costs its OWN dice (disintegrate 5d6, slay living 3d6+CL,
  destroy robot) still deals 0 on a save and is told: rolling a second formula needs the
  player's-own-dice suspension path for a second roll.
- Rays and missiles by count (admonishing ray, fiery shuriken) need `MISSILE_SPELLS` rows.
